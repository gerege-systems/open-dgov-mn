# Аюулгүй байдал

## Баталгааны нэг гинж

```
eID / ДАН / нууц үг
      ↓
серверийн session
      ↓
байгууллагын гишүүнчлэл
      ↓
роль ба зөвшөөрөл
      ↓
OIDC клиент
```

Алхам бүр сервер талд шалгагдана. Хөтчөөс ирсэн ямар ч мэдэгдэл эрх
олгодоггүй — хөтөч зөвхөн cookie авчирдаг, түүнээс цааш бүх зүйл серверийн
шийдвэр.

## Юу хаана хадгалагддаг вэ

| Зүйл | Хэлбэр |
| --- | --- |
| Session токен | Зөвхөн hash. Санг уншсан хүн сесс хулгайлж чадахгүй |
| Нууц үг | bcrypt |
| OAuth2 клиентийн нууц | Зөвхөн digest. Үүсгэх үед нэг л удаа уншигдана |
| Federation-ы IdP secret, SCIM токен | AES-GCM шифрлэлт |
| Session cookie | `httpOnly`, `SameSite` |

Итгэмжлэлийг шифрлэх түлхүүр байхгүй бол платформ асна, бусад бүх дэлгэц
ажиллана — татгалзах зүйл нь итгэмжлэлийг цэвэр текстээр хадгалах гэсэн
бичилт. Түлхүүрээ солих нь хадгалагдсан итгэмжлэлүүд задрахаа болино гэсэн
үг.

## Тусгаарлалт

Байгууллага бүр тусдаа тенант. Асуулга бүр байгууллагаараа хязгаарлагдана,
энэ нь аппын кодын сахилга бат дээр биш өгөгдлийн сангийн мөрийн түвшний
хамгаалалт (RLS) дээр тогтоно. Модуль бичигч үүнийг санах шаардлагагүй,
санахаа мартах ч боломжгүй.

Суулгаагүй модуль руу хандвал хориглоно — код нь бинарид байгаа ч тухайн
байгууллагад хаалга нь хаалттай.

## Redirect

`redirect_uris` яг таг тааралдана. Wildcard байхгүй, дэд домэйн
өвлөгдөхгүй. Дээр нь хостын allowlist — хоёр дахь шалгалт нь буруу
бүртгэгдсэн клиентийг нэг хүний алдаанаас бус, хоёр хүний алдаанаас л
гардаг болгож байгаа хэрэг.

## Хурдны хязгаарлалт

Нэвтрэлтийн хаягууд орох цэг дээрээ хязгаарлагдана. API-гийн хуулбар
нэмэгдэхэд халдагчийн нууц үг таах төсөв хамт үржих ёсгүй.

## Нээлттэй зам

Нэвтрэлтийн үйлчилгээ дээр баталгаажуулалтгүй зам **нэг ч байхгүй**.
Үүнийг тест барина: шинэ endpoint нэмэхдээ санамсаргүйгээр нээлттэй
үлдээвэл CI унана.

## Аудит

Хэн юуг хэзээ өөрчилснийг эхний өдрөөс бичнэ. Сесс таслалт бүр хэн
тасалсан, яагаад гэдгээ үлдээнэ.

# Засгийн газрын нэгдсэн нэвтрэлт

**[sso.dgov.mn](https://sso.dgov.mn)**

Хэн болохыг тогтоодог цорын ганц газар. Энэ үйлчилгээ өөр юу ч хийхгүй —
бараа ч бүртгэхгүй, тайлан ч гаргахгүй. Танилт, сесс, эрх, хэрэглэгчийн
амьдралын мөчлөг: дөрөв.

Тэр хязгаарлалт нь дутагдал биш. Хэн нэвтрэх эрхтэйг шийддэг систем бол
санамсаргүйгээр нэмэлт гарц ургуулах хамгийн сүүлийн газар. Тиймээс
баталгаажуулалтгүй нээлттэй зам энд **нэг ч байхгүй**, түүнийг тест барина.

## Юу шийддэг вэ

### Танилт — OAuth2 / OIDC провайдер

Холбогдсон систем бүр хүнийг эндээс танина. Стандарт discovery:

```
https://sso.dgov.mn/.well-known/openid-configuration
https://sso.dgov.mn/.well-known/jwks.json
```

`authorization_code` + PKCE, RS256-аар гарын үсэг зурсан id token. Онцгой
протокол байхгүй — ямар ч OIDC клиентийн сан ажиллана.

Танилтын арга нь eID (регистрийн дугаараар түлхэлт, QR, App2App), ДАН,
эсвэл нууц үг. Аль нь ч байсан гарах үр дүн нь ижил: серверийн session,
`httpOnly` cookie, hash хэлбэрээр хадгалагдсан токен.

### Идэвхтэй сесс

Холбогдсон бүх системийн идэвхтэй сессүүд нэг жагсаалтад: хэн, хаанаас,
хэзээ сүүлд харагдсан.

Нэг сессийг эсвэл нэг хүний бүх сессийг **алсаас таслана**. Таслалт бүр хэн
тасалсан, яагаад гэдгийг бүртгэнэ. Хүний бүх сессийг таслахад шалтгаан
заавал бичигдэнэ — тэр хүнд хэлэх хариулт байх ёстой.

Хулгайлагдсан утас, ажлаас гарсан хүн, эргэлзээтэй нэвтрэлт: хариу үйлдэл нь
систем бүрээр тойрч явах биш, нэг товч.

### Эрхийн хяналт

Хэн юунд хандах эрхтэйг үе үе дахин баталгаажуулах кампанит ажил.

Кампанит ажил нээгдэх агшинд эрхийн төлөвийг **хуулж авна**. Дараа нь эрх
өөрчлөгдсөн ч хянагдаж байсан зүйл өөрчлөгдөхгүй — амьдаар уншдаг байсан
бол Мягмар гарагт хийсэн засвар Даваа гарагт хэн нэгний баталгаажуулсан
зүйлийг чимээгүй дахин бичих байв.

`draft → open → closed`, буцах зам байхгүй. Хаагдсан кампанит ажлыг дахин
нээвэл эцсийн гэж мэдээлсэн шийдвэр өөрчлөгдөх боломжтой болно.

Автоматаар олгогддог өгөгдмөл роль ч хамрагдана — хэний ч гараар өгөгдөөгүй
эрх учраас яг л хянагдах ёстой зүйл.

### Хэрэглэгч нийлүүлэлт (SCIM 2.0)

Хүний бүртгэлийг холбогдсон систем рүү нэг чиглэлд түлхэнэ. Дараалал нь
`FOR UPDATE SKIP LOCKED`-оор уншигдаж, амжилтгүй ажил ухарч давтагдаад
бүртгэл үлдээж зогсоно.

### Холбоос нэвтрэлт (federation)

Байгууллага өөрийн итгэх гадны IdP-үүдээ бүртгэнэ: issuer, client id,
шифрлэгдсэн secret, scope, claim-ийн зураглал.

Хадгалагдсан secret нь **буцаж уншигдахгүй** — API нь зөвхөн байгаа эсэхийг
хэлнэ. Шифрлэлт нь AES-GCM.

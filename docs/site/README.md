# Баримт бичгийн сайт

Энэ хавтас нь [gerege-systems.github.io/open-dgov-mn](https://gerege-systems.github.io/open-dgov-mn/)
хаяг дээр нийтлэгддэг сайтыг угсарна. Хоёр landing page-ийн «Баримт бичиг»
цэс энэ рүү заана (`BRAND_DOCS_URL`).

**Баримтын эх сурвалж нь энэ хавтас биш.** Сайт нь репод аль хэдийн байгаа
Markdown файлуудаас угсрагддаг: `docs/*.md` ба `README.md`. Тиймээс баримт
засах гэдэг нь Markdown файлаа засахаас өөр юм биш — энд юу ч хийх
шаардлагагүй. Файлууд GitHub дээр хэвээрээ уншигдана.

Угсрагч нь [цөмийн `docs/site`](https://github.com/gerege-systems/open-gerege-nexus/tree/main/docs/site)-аас
хуулагдсан бөгөөд PAGES жагсаалт, толгойн брэнд, хоёр хэл гэсэн гурван
зүйлээрээ ялгаатай.

## Ажиллуулах

```bash
cd docs/site
npm ci
npm run check      # угсраад холбоосуудыг шалгана
npm run serve      # http://localhost:4321
```

## Юу нийтлэгдэхийг хаанаас шийддэг вэ

`build.mjs` доторх `PAGES` жагсаалт. Шинэ баримт нэмэхэд тэнд нэг мөр
нэмнэ — `src`, `slug`, `title`, `group`. Мөр нэмэхгүй бол баримт сайт дээр
гарахгүй; түүн рүү холбоос байвал CI холбоосын шалгалт дээр унана.

Репогийн үндсэн `README.md` нь «Байрлуулалт» хуудас болж нийтлэгдэнэ.
Операторын хуудсыг хоёр газар бичих нь хоёр газар үнэн байлгах шаардлага
үүсгэнэ.

## Холбоос хэрхэн ажилладаг вэ

Markdown доторх холбоос нь тухайн файлаасаа харьцангуй байдаг ба сайт нь
хавтасгүй тул `build.mjs` холбоос бүрийг гурван газрын аль нэг рүү
чиглүүлнэ: нийтлэгдсэн өөр баримт → түүний хуудас, `docs/assets/` доторх
файл → хуулагдсан файл, бусад бүх зүйл → GitHub дээрх файл.

## CI

[`.github/workflows/pages.yml`](../../.github/workflows/pages.yml) нь `main`
дээрх баримт өөрчлөгдөх бүрд сайтыг угсарч нийтэлнэ. Pull request дээр
угсралт ба холбоосын шалгалт ажиллах ч нийтлэхгүй — эвдэрсэн холбоос нь
нийтлэгдсэний дараа биш, өмнө нь баригдана.
